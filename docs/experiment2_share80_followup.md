## Exact Grid commands

Run these from the CBS Research Grid login shell. Run each numbered block only after the preceding stage has completed. The commands use the existing `qsub` convention from the historical meaningful-Pareto validation, with 20 concurrent tasks and one worker per task.

### 1. Initialize and count discovery work

```bash
cd "$HOME/projects/CUIMC-Appointment-Simulation"
export REPO="$PWD"
export PYTHON="$HOME/.conda/envs/cuimc/bin/python"
export PBF_FOLLOWUP_ROOT="/scratch/$USER/patient_behavior_factorial_share80"
export PBF_FOLLOWUP_BANK="$REPO/outputs/hypotheses/patient_behavior_factorial_share80_bank.csv"
export SHARD_COUNT=54
export PYTHONPATH="$REPO${PYTHONPATH:+:$PYTHONPATH}"
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1
export PYTHONUNBUFFERED=1 PYTHONHASHSEED=0
chmod +x jobs/run_experiment2_share80_followup.sh
bash -n jobs/run_experiment2_share80_followup.sh
mkdir -p "$PBF_FOLLOWUP_ROOT" grid_logs/experiment2_share80/{search,catalog,evaluate,postprocess}

STAGE=bank bash jobs/run_experiment2_share80_followup.sh
STAGE=search DRY_RUN=1 bash jobs/run_experiment2_share80_followup.sh
```

A fresh run prints **540,270 planned / 540,270 pending**. This is the full original coarse policy grid on five seeds over only 54 clinic backgrounds. Do not use the old preparation script: these backgrounds are new and cannot reuse historical raw shards.

### 2. Submit discovery

```bash
qsub -N e2s80_search -cwd -V -t 1-54 -tc 20 \
  -v STAGE=search,SHARD_COUNT=54 \
  -o grid_logs/experiment2_share80/search \
  -e grid_logs/experiment2_share80/search \
  jobs/run_experiment2_share80_followup.sh
qstat -u "$USER"
```

After discovery finishes, require zero pending work:

```bash
STAGE=search DRY_RUN=1 bash jobs/run_experiment2_share80_followup.sh
```

If pending is nonzero, inspect failed tasks and resubmit the same array. Completed rows are skipped. Never start the catalog until pending is zero.

### 3. Freeze all meaningful candidates

```bash
qsub -N e2s80_catalog -cwd -V -v STAGE=catalog \
  -o grid_logs/experiment2_share80/catalog \
  -e grid_logs/experiment2_share80/catalog \
  jobs/run_experiment2_share80_followup.sh
qstat -u "$USER"
```

Wait for successful completion, then count independent validation work:

```bash
STAGE=evaluate DRY_RUN=1 bash jobs/run_experiment2_share80_followup.sh
```

The catalog explicitly rejects incomplete discovery. Candidate count and validation workload depend on the discovery results. Do not rerun catalog while validation is underway; the candidate file defines the frozen discovery set.

## What is preserved

- **54 backgrounds**: share 0.8 × capacities 30/40/50 × rho 1.7/2.0 × nine profiles. Total arrival rate is `rho × capacity`; arrivals are split 80%/20%.
- Existing `_profiles()` supplies all behavior/cancellation assumptions unchanged. C1: no-show threshold 3, pre 0.05, post 0.05/0.15/0.25; balking threshold 5, pre 0.05, post 0.10/0.20/0.30. C2: no-show `(14, 0.05, 0.15)`, balking `(16, 0.05, 0.15)`; cancellation 0.20 for both classes; thresholds are not capped to horizon.
- Baseline is `(H=100, Q=0, W=-1)`, paired on the same seeds as each candidate. Baseline simulations are necessary for the comparison.
- Both-flexible coarse grid: H=2 through 30, Q=5/10/.../capacity, W from the existing odd-day grid plus its upper endpoint, capped at `min(H,26)`. W=1 is simulated to preserve the original grid but excluded from genuine-reservation catalog eligibility, exactly as in the historical extractor. No Q=0 horizon cells or H=100 reservation cells are searched.
- Discovery seeds **1000–1004**. Use only systematic coarse cells with **Q>0 and W>=2**. Freeze **every** cell with mean paired C1 and C2 deltas both >=0 and at least one >=0.005 (0.5 percentage points).
- Validate frozen candidates and matched baseline on **2000–2019**, using the existing evaluator and resume keys. Keep a validated cell if both independent mean deltas are >=-1e-12 and one is >=0.005. A background succeeds if any candidate validates.
- Preserve the historical postprocessor's **2,000 paired bootstrap draws**, 95% intervals, RNG seed 20260928, and separate statistical-support flags. Confidence intervals do not replace the point-estimate eligibility rule.
- Reuse existing simulation/config/task helpers: 30 burn-in days, 365 measurement days, cooldown `max(14,H)`, same-day cancellation and release of unused Class 1 reservations. No simulation engine changes.
- No utilization objective, selected-winner shortcut, separate horizon-only/reservation-only runs, adaptive refinement, normalized reservation-fraction grid, or broad capacity/share expansion.

## Minimal changes and validation

Two additive files: a dedicated Python runner with bank/search/catalog/evaluate/postprocess stages, and one Grid wrapper. The runner reuses project helpers, incorporates the both-flexible portion of the historical five-seed extractor and evaluator recovered from the referenced conversation, and preserves the existing postprocessor calculations. Those historical extractor/evaluator files were present in the Grid conversation but absent from this local checkout, so the new runner is self-contained.

The distinction matters: `analysis/patient_behavior_factorial_served_rate_pareto.py` describes a 5/10/20-seed selected-policy workflow, but the **33-background result** came from the later systematic **5-seed catalog / all-candidate 20-seed validation**. This follow-up matches the latter.

Local verification passed: exact 54-background bank, 540,270-run discovery dry-run, active-reservation/systematic-arm filtering, independent seed separation, paired validation, zero-pending resume, rejection of incomplete discovery, and all 54 reporting denominators retained even with no candidates. Synthetic data were used to exercise validation; no real simulation results were generated.

The local Windows environment could not start Bash for syntax verification; `bash -n` is included in the Grid initialization block. No Grid jobs were submitted from this session.
